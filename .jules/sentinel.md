## 2024-05-24 - Content Security Policy Implementation
**Vulnerability:** Missing Content Security Policy (CSP). The `index.html` file did not have a CSP defined, making the application potentially vulnerable to Cross-Site Scripting (XSS) and unauthorized data transmission.
**Learning:** Modern web applications, especially those that include third-party content like map tiles and API responses, need a robust CSP to restrict where resources can be loaded from and where connections can be made to. The project uses various external services (RainViewer, OpenFreeMap, Carto, ArcGIS, GitHub User Content, Google Fonts), all of which need to be explicitly allowed.
**Prevention:** Include a comprehensive `<meta http-equiv="Content-Security-Policy">` tag in `index.html` that follows the principle of least privilege, explicitly allowing only necessary domains for `connect-src`, `img-src`, `style-src`, and `font-src`. Ensure that any new external service added in the future is also updated in the CSP.
